# Theming

Theming is done entirely with CSS variables, so you can restyle the library with plain CSS
and no rebuild. There are two independent choices, plus your own overrides.

## Try it live

Switch the style and color scheme, or override one token, and watch real components follow.
Only the box below is themed; the rest of this page is not.

<ThemePlayground />

## Style and scheme

| Attribute | Values | Default |
| --- | --- | --- |
| `data-style` | `glass`, `brutal` | `glass` (attribute absent) |
| `data-theme` | `light`, `dark` | follows the operating system (attribute absent) |

Put both on `<html>`, or on any element to theme just that subtree:

```html
<section data-style="brutal" data-theme="dark"> … </section>
```

### In React

`ThemeProvider` manages the color scheme: it sets `data-theme`, remembers the choice, and follows the system by default.

```tsx
import { ThemeProvider, useTheme } from "northlight-ui";

function ThemeToggle() {
  const { theme, setTheme } = useTheme();
  return <button onClick={() => setTheme(theme === "dark" ? "light" : "dark")}>Toggle</button>;
}
```

Switching `data-style` is up to you (a single attribute). `ThemeProvider` does not manage it yet.

### Avoid a flash on first paint

On a server-rendered page the saved theme is only known in the browser. Render this script in `<head>`:

```tsx
import { getThemeInitScript } from "northlight-ui";

<script dangerouslySetInnerHTML={{ __html: getThemeInitScript() }} />
```

That string is generated by the library, never from user input.

## Overriding tokens

Components read **semantic** tokens. Override them with ordinary CSS, in your own stylesheet, after the library's:

```css
:root {
  --nl-color-action: #0d9488;
  --nl-radius-md: 0.25rem;
}

/* Only in dark mode */
[data-theme="dark"] {
  --nl-color-action: #2dd4bf;
}
```

> If you change a color, check the text on top of it. Contrast is not recalculated for you; the numbers on the
> [Colors page](?path=/docs/design-tokens-colors--docs) show how to read it.

## The token layers

1. **Primitive** (`--nl-color-indigo-600`): raw values. Don't use them in components.
2. **Base** (`--nl-radius-md`, `--nl-border-width-control`): shape, per style, the same in light and dark.
3. **Semantic** (`--nl-color-action`, `--nl-shadow-md`): meaning, per style and per scheme. This is what components use.

## Making your own style

A style is an object in `packages/tokens/src/tokens.json` under `styles`, with `base`, `light` and `dark` groups.

1. Copy an existing style and rename it.
2. Change values. Keep **every token name**: the token tests fail if a style is missing one that another defines,
   because components would break in it.
3. Run `pnpm --filter northlight-ui-tokens build`. The CSS for `data-style="yourname"` is generated for you.
4. Run `pnpm --filter northlight-ui-tokens test`. It checks that every reference resolves, that light and dark match,
   and that button labels meet 4.5:1 on every gradient stop.
5. Run `pnpm a11y` to check the real components in a browser.
